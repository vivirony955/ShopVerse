# Plugin Accessibility

Plan §10 E17 — slot components must clear axe-core at severity
`serious` or `critical`. The CI gate is enforced by
[W5.T5 jest-axe iterate-all-slots test](../../frontend/src/lib/__tests__/slots.a11y.test.tsx).

## Hard rules

For each slot component:

1. **Semantic HTML** — interactive elements use the right tag.
   - Button → `<button>`. Not `<div role="button">`.
   - Link → `<a href>`. Not `<button onClick={() => router.push(...)}>`.
   - Toggle → `<button aria-pressed>` for in-place toggle, or
     `<input type="checkbox">` for forms.
2. **Focus management**
   - Slot inserted in a modal MUST NOT trap focus inside itself —
     the modal manages the focus trap.
   - First focusable child must be reachable via tab from the
     parent's last focusable element.
3. **`aria-label` on icon-only buttons** — every `<button>` whose
   visible content is just an icon component needs `aria-label`.
   The icon component itself should be `aria-hidden="true"`.
4. **`prefers-reduced-motion`** — animations must check the media
   query:
   ```ts
   import { useReducedMotion } from 'framer-motion';
   const shouldReduceMotion = useReducedMotion();
   ```
5. **Colour contrast** — text + background must meet WCAG AA (4.5:1
   for body text, 3:1 for large text). Tailwind defaults are usually
   safe; check custom hex codes via the inspector.
6. **Forms** — every input has a label (`<label htmlFor>` or
   `aria-labelledby`); error messages connect via
   `aria-describedby`.

## The CI gate

`frontend/src/lib/__tests__/slots.a11y.test.tsx` iterates every
entry in `ALL_PLUGIN_SLOTS`, renders the component in jsdom with
representative props, and runs `axe`. Default rule set fails on
`serious` and `critical` violations.

Run locally:

```bash
cd frontend && npm test
```

If your plugin component pulls in providers (`SessionProvider`,
`QueryClientProvider`), the iterate-all-slots test mocks the
relevant hooks at the test level. If your component uses a hook the
mock list doesn't cover, extend
[slots.a11y.test.tsx](../../frontend/src/lib/__tests__/slots.a11y.test.tsx).

## What axe catches (sample)

- `button-name`: button without accessible name
- `color-contrast`: text/background ratio too low
- `label`: form input missing label
- `link-name`: link without accessible name
- `aria-required-attr`: missing required ARIA attribute
- `aria-roles`: invalid role value
- `landmark-one-main`: page missing `<main>` (kernel concern, not plugin)
- `region`: content outside any landmark (often false-positive in
  isolated slot rendering — suppressable)

## What axe does NOT catch

- Cognitive accessibility (reading level, complexity)
- Keyboard-only-path reachability beyond focus (e.g. you can tab to
  a button but pressing it requires a Ctrl-modifier you didn't
  document)
- Visual focus indicators when overridden by your styles
- Screen-reader narration order

You're responsible for manually testing keyboard navigation and
screen-reader behaviour for any non-trivial slot. The CI gate is the
floor, not the ceiling.

## Common quick fixes

| Violation | Fix |
|---|---|
| Icon-only `<button>` | Add `aria-label="Notify me"` on the button, `aria-hidden="true"` on the icon |
| Toggle button missing state | Add `aria-pressed={hasAlert}` |
| Animated dialog without reduced-motion check | `useReducedMotion()` from framer-motion |
| Custom dropdown without keyboard | Use Radix UI / shadcn primitives, don't roll your own |
| Form input missing label | `<label htmlFor="email">Email</label><input id="email" />` |
| Low-contrast hover state | Test in the inspector, bump the colour darkness |

## Authoring help

When you write a new slot component, run:

```bash
cd frontend && npm test slots.a11y -- --watch
```

The watch mode re-runs axe on every save. Fail fast.
