## Edge Cases (Explicitly Resolved)

**"I'm building a prototype for a potential client"**
→ Once you show a prototype to a potential paying client, this is a commercial context. Get a license before the client engagement begins.

**"My store makes very little money — maybe ₹5,000/month"**
→ Any revenue = commercial use. The startup tier license applies. Price it as a cost of doing business.

**"I forked ShopVerse and renamed it"**
→ ELv2 follows the software, not the name. All forks and derivatives carry the same license obligations.

**"We're using only some modules, not the full platform"**
→ ELv2 applies to any part of the codebase used in a commercial context, not only the whole system.

**"We're running it internally, employees don't pay"**
→ Internal business deployment is commercial use. If your organization earns revenue and uses ShopVerse operationally, a license is required.

**"We're a non-profit but we have a small shop"**
→ If the shop generates revenue (even to fund operations), it is commercial use.

**"We want to offer ShopVerse as a hosted service but open-source our additions"**
→ This is still a managed hosted service — ELv2's primary restriction. A commercial license is required regardless of what you open-source.

**"I'm a solo developer, this is my side project that earns some money"**
→ Revenue = commercial. Startup tier license applies. It's priced to be affordable.

## Why We Use This Model

ShopVerse is built by a single developer and represents years of engineering work — multi-warehouse inventory routing, race-safe financial invariants, 638 production-grade tests, full security hardening. Permissive licenses (MIT, Apache) would allow commercial actors to build products on this work with zero obligation to contribute back or pay.

ELv2 makes ShopVerse sustainable: non-commercial users get full access for free; commercial users fund the continued development of the platform.
